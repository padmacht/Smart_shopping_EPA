# ShopSmart v3 Dataset: Data Card

A synthetic e-commerce dataset built for the **ShopSmart AI** project (customer segmentation +
recommendations + AI shopping assistant). It is large and structured enough for **deep learning**,
and it contains hidden behaviour patterns, so every model has something real to discover.

> **Synthetic data.** Generated by `generate_dl_dataset.py` (seed 42). The patterns were designed,
> not observed. Use it to demonstrate methods, and say so in your report.
> Regenerate with: `python generate_dl_dataset.py --users 5000 --products 1500 --seed 42 --outdir data_v3`

## Files at a glance

| File | Rows | What it is | Main use |
|---|---|---|---|
| `products.csv` | 1,500 | Catalogue: 9 categories, 90 product types | Content features, search, chatbot answers |
| `user_data.csv` | 5,000 | Customer profiles | Segmentation, cold start |
| `interaction.csv` | 354,340 | Event log in 43,111 sessions (Nov 2024 – Oct 2026) | Recommenders, sequences, RFM, funnel |
| `reviews.csv` | 7,243 | Written reviews with 1–5 star ratings | Sentiment analysis (NLP/DL) |
| `search_queries.csv` | 515 | Search queries with the correct products labelled | Evaluating keyword vs semantic search |
| `chatbot_intents.csv` | 2,560 | Chatbot messages labelled with 16 intents + entities | Intent classifier, entity extraction |
| `faq.csv` | 16 | Shop policies (delivery, returns, payment…) | Chatbot answers / RAG |
| `customer_personas_truth.csv` | 5,000 | **Hidden** true persona and churn per customer | **Evaluation only, never a feature** |

## Columns

**products.csv**: Product ID, Product Name, Category, Product Type, Brand, Description (40–80 words),
Price (£), Colour, Size, Material, Age Range, Tags, Avg Rating, Num Reviews, In Stock, Stock Qty,
Delivery Days, Launch Date (products launched after the data starts only appear from that date).

**user_data.csv**: User ID, Age, Gender, Location, Signup Date, Preferred Device, Newsletter,
Browsing History (categories viewed), Purchase History (product IDs bought).

**interaction.csv**: Event ID, User ID, Product ID, Session ID, Interaction Type
(`view` 187k, `click` 92k, `add_to_cart` 39k, `purchase` 22k, `rating` 10k, `wishlist` 5k),
Timestamp, Rating (only on `rating` events, 1–5), Device, Quantity and Price (only on `purchase` events).

**reviews.csv**: Review ID, User ID, Product ID, Rating, Review Title, Review Text, Review Date, Verified Purchase.

**search_queries.csv**: Query ID, Query, Query Type (`keyword`, `semantic`, `filtered_price`,
`filtered_brand`, `filtered_colour`, `gift`), Relevant Product IDs (pipe-separated).

**chatbot_intents.csv**: Utterance ID, Text, Intent (16 classes, 160 each), Entities (JSON, e.g.
`{"price": "50", "brand": "VoltEdge"}`), Template ID (use it for grouped splits; see below).

## Key statistics
- 21,847 purchases by 4,505 buyers · revenue ≈ £996k · average item price £44.44
- User–product matrix density 2.3% (15,000 interactions in v2 gave 0.7%)
- Funnel: view → click 49% · click → cart 42% · cart → purchase 57% · 38% of sessions convert
- Strong seasonality: November and December carry about 24% of traffic
- 18% of customers churn (stop shopping) during the period
- Ratings: 5★ 33% · 4★ 28% · 3★ 23% · 2★ 12% · 1★ 4%

## Hidden patterns (what models should discover)

| Pattern | How it was generated | Model that should find it |
|---|---|---|
| **8 personas**: Bargain Hunter, Premium Loyalist, Young Techie, Busy Parent, Fitness Enthusiast, Self-Care Lover, Bookworm Homebody, Seasonal Gifter | Each has its own category tastes, price sensitivity, brand loyalty, activity, device, churn and age range | K-Means / GMM, **autoencoder** clustering |
| **Latent taste** | Every customer and product has a hidden 8-dimensional vector; affinity is their dot product | Matrix factorisation, **NCF / two-tower** |
| **Complementary purchases** | After buying e.g. a Yoga Mat, the next session often targets a Foam Roller or Water Bottle | **Sequence models** (GRU4Rec, SASRec), association rules |
| **Price sensitivity & brand loyalty** | Bargain Hunters avoid expensive items; Premium Loyalists favour premium brands | Feature importance, segment profiles |
| **Seasonality** | Gift items peak in Nov–Dec, summer items in Jun–Aug, winter items in Nov–Feb | Time features, forecasting |
| **Ratings** | Rating = customer–product affinity + product quality + noise | Rating prediction |
| **Review sentiment** | Text follows the rating, but ~15% of reviews read like a neighbouring rating; includes negation ("not bad at all"), mixed reviews and filler sentences | LSTM / **BERT** sentiment |
| **Semantic search** | Natural phrases with few shared words ("something to help me sleep" → Weighted Blanket) | **Sentence embeddings** + FAISS |

## Baseline results (classic ML, `validate_dl_dataset.py`)
These are the numbers your deep learning models should try to beat.

| Task | Baseline | Result | Room for DL |
|---|---|---|---|
| Recover personas | K-Means (k=8) on RFM + category mix | ARI **0.26** | Autoencoder embeddings, GMM |
| Recommend (time split) | Popularity / Item-KNN / SVD | HitRate@10 **0.122 / 0.141 / 0.091** | Two-tower, NCF, SASRec |
| Next-purchase complement | Observed rate vs random | **27.6% vs 2.4%** (11.5× lift) | Sequence models |
| Sentiment (3 classes) | TF-IDF + logistic regression | Macro-F1 **0.90** | Fine-tuned DistilBERT |
| Search: semantic queries | TF-IDF | Hit@10 **0.53** (keyword queries: 1.00) | Sentence-transformers |
| Intent: random split | Char TF-IDF + logistic regression | Accuracy **0.996** | – |
| Intent: **unseen templates** | Same model | Accuracy **0.45** | Embeddings, BERT, LLM |

**Finding:** on this larger dataset, plain Item-KNN beats the hybrid recommender from v2
(NDCG@10 0.042 vs 0.038). With more data, collaborative signal matters more than popularity.

## How to use it correctly
- **Recommenders and sequences:** split by **time** (e.g. the last 20% of time as test), never randomly.
- **Segmentation:** build features only from users, interactions and products. Use
  `customer_personas_truth.csv` *only* to score clusters (ARI, NMI) after clustering.
- **Intents:** report both a random split and a **grouped split by Template ID**. The grouped split
  tests whether the model understands phrasing it has never seen.
- **Sentiment:** map ratings 1–2 to negative, 3 to neutral, 4–5 to positive; classes are imbalanced
  (60/24/16), so use macro-F1 and class weights.
- **Search:** compute Hit@10 / Precision@10 / MRR per query type; the `semantic` queries are the hard ones.

## Which model uses which file

| Project module | Concepts | Files |
|---|---|---|
| A. Segmentation | RFM, K-Means, GMM, PCA/UMAP, **autoencoder** | user_data, interaction, products (+ truth for evaluation) |
| B. Recommendations | Popularity, Item-KNN, SVD, hybrid, **NCF / two-tower**, **GRU4Rec / SASRec** | interaction, products, user_data |
| C. Assistant: search | TF-IDF vs **sentence embeddings + FAISS** | products, search_queries |
| C. Assistant: chatbot | Intent classification, entity extraction, **LLM + RAG + tool use** | chatbot_intents, faq, products, reviews |
| Extras | Sentiment (LSTM/BERT), churn prediction, demand forecasting, funnel analysis | reviews, interaction, customer_personas_truth |

## Limitations
- Synthetic: real customers are messier, and there is no returns, pricing-change or marketing-campaign data.
- Review and chatbot text come from templates; real text is more varied.
- Product descriptions follow a common structure, so some features can be phrased oddly.
